# 小汐换机与接入验收

## 第一次运行或更换电脑

在新电脑取一份干净的仓库，把它放在自己有写权限的目录。以下命令都在有 `package.json` 的那一层运行。仓库名和上级目录可以包含空格、中文。先运行 `node --version` 确认浏览器版所需的 Node.js 至少为 20.16。离线演示本身无需 Python、微信、Electron 或模型账号，首次安装 npm 依赖需要能够取得锁文件指定的软件包。

```sh
npm ci --omit=optional
npm run init
npm run demo -- --smoke
npm run doctor -- --json
```

| 看到的结果 | 可以继续做什么 |
| --- | --- |
| smoke 输出 `"mode":"mock"`、`"panel":true` 并退出 | 本机浏览器面板已通过一次 HTTP 试聊。运行 `npm run demo`，打开终端打印的地址，在“本地试聊”输入一句话。 |
| 全新安装的 doctor 显示 `configuration: configured`、`modelProvider: mock`、`targets: 0` | 部署文件已创建，可以打开 `npm run panel` 配置自己的模型。doctor 只读取部署文件中的模型默认值，面板已经保存的模型以面板显示为准。 |
| 端口已占用 | 给刚启动的演示加 `--port`，例如 `npm run demo -- --port 8766`，打开本次终端打印的地址。正式面板也接受这个参数。 |

在其他工作目录运行时，把绝对仓库路径放进 `--prefix`。例如在 PowerShell 中打开仓库目录一次，运行 `$repo = (Get-Location).Path`，之后可以切到其他目录，执行：

```powershell
npm --prefix "$repo" run doctor -- --json
npm --prefix "$repo" run demo -- --smoke
```

在 macOS/Linux 的终端中，在仓库目录执行 `repo="$(pwd)"` 后也可以使用同样两行 npm 命令。若已通过 `XIAOXI_CONFIG` 指定自有部署文件，请设置成**新机器的绝对路径**。这个变量只选择部署文件；人格卡、面板状态和插件仍在当前仓库中寻址。

## 哪些东西值得迁移

| 旧设备上的东西 | 在新设备上怎么做 |
| --- | --- |
| 自己编辑的 `character_card.local.json` | 需要沿用角色时复制到新仓库根目录。卡里的 `id` 应与新部署的 `character.id` 一致。在“人格与参与”核对称呼和表达。 |
| `deployment.local.json`，或 `XIAOXI_CONFIG` 指向的文件 | 先用 `init` 建立空配置，再按需填回会话 ID、名称和模型默认值。保留同一会话原先的 `targets[].id`。在新机重新核对账号目录、目标群和插件授权。 |
| API 凭据、模型选择和设置 | 在新机给启动进程设置自己的密钥环境变量，在“模型与启动”填写变量名、端点和模型名并保存。在“连接与状态”点“测试 AI”会实际调用所选模型。 |
| 自写插件 | 将经过审阅的源码和它需要的本机依赖移入新仓库，核对 `extensions[].module`。先启动正式面板在“本地试聊”验证；演示模式会忽略插件。[插件契约和示例](EXTENDING.md) |
| Electron 加密聊天、浏览器聊天、提醒和长期记忆 | 各运行模式分别保存。模板没有跨设备导入这些状态的命令；需要保留历史时保管原设备上的原件。新机按空状态启动，重新确认需要的提醒。 |
| `node_modules/`、Python 虚拟环境、DLL 兼容报告、微信窗口绑定 | 按新机重新安装和验证。浏览器路线到此就可用；只有 Windows 微信原生收发需要下一节。 |

## 接入一个 Windows 测试群

1. 在“账号与授权”填机器人账号及一个准备测试的群，在 Windows 微信中双击该群打开独立窗口。按 [Windows 微信接入步骤](../README.md#微信接入先明确限制再配置) 安装 Python 依赖，并对本机的 DLL 运行 `npm run native:prepare`。受支持的精确版本与哈希见 [native_builds.json](../native_builds.json)。
2. 换机时先在新设备完成本地试聊和模型测试。准备连接真实群时，在旧设备停止监听，确认已停再进入下一步。
3. 正常重启新机上的正式面板或桌面客户端，连接微信。先看目标群的读取状态。群窗口可以最小化。首次启动时已有聊天只作为基线，用另一个号在目标群发一条**新的**、带角色称呼的问题。
4. 在对方手机或客户端核对回答是否到达，同时观察电脑是否切走了当前应用。运行记录中的 `local_echo` 只说明本机出现发送气泡。发送结果不明时，先在该群核对消息和草稿，再决定是否恢复。如需回退，先停止新机监听，再恢复旧机。

## 按故障位置排查

群窗口最小化时，微信可能仍显示“新消息”提示。小汐会对照上次读到的最后两个气泡，只处理能确认连续出现的新消息。窗口暂时停在旧位置时，小汐会保留读取位置最多一分钟。如果面板提示跳到最新，打开对应群并点未读提示即可；窗口恢复后会自动复查。换了窗口、超过一分钟或消息接不上时，从当前画面重新开始监听。

微信收发期间关机或关闭程序，重开后可在“会话管理”查看对应群。回复还在本机准备、或微信因草稿而明确暂缓时，中断会记为 `not_sent`。已进入提交阶段且缺少最终回执时，记为 `unknown`，暂停该群；其他群可继续工作。先在该群核对消息和输入框，确认后点“已核对微信，恢复本群”。重新连接只重建窗口，恢复后的第一步是建立当前基线，两种操作都不补发旧回复。提醒遵循同样的回执；若只找到已经领取任务的记录、缺少发送证据，显示结果未知。

| 现象 | 下一步 |
| --- | --- |
| 演示正常，正式面板没有使用选定的模型 | 确认打开的是 `npm run panel` 输出的地址。“本地试聊”可独立于微信工作。检查启动面板进程是否继承了密钥变量，再手动“测试 AI”。 |
| 修改配置后群没有出现 | 核对当前仓库和 `XIAOXI_CONFIG`。会话授权在启动时加载，保存后正常退出并重开正式实例。 |
| 模型能回答，但群里无响应 | 到“连接与状态”看微信连接，再到“会话管理”核对目标群已启用、参与模式允许回复、独立窗口仍打开。先用另一账号发新的叫名消息。 |
| 更换微信版本后报告 `unsupported_wechat_build` | 核对 [精确构建清单](../native_builds.json)。保留浏览器和模型能力，等待新适配器通过验证，或按 [扩展契约](EXTENDING.md) 实现对应版本。 |
| Windows 双击面板没有启动 | 在仓库目录执行 `./Start_Panel.cmd --check`。缺少依赖时重跑精简安装，再执行 `npm run panel` 查看终端报错。 |

提交问题时附系统、Node 与微信版本、使用的启动命令、哪一步通过以及哪一步失败即可。把测试会话表述为“测试群 A”，移除日志里的账号标识和本机路径。
