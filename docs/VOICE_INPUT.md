# 群语音和本机录音

## 想让小汐自动接群里的语音

在机器人使用的电脑微信打开设置，查找 **聊天中的语音消息自动转成文字**。微信 4.1.15.56 安装文件包含这项设置的中文名称。它是微信自身的设置，适用范围由微信决定。小汐只处理主人授权且正在监听的会话，不会代为打开设置或触发右键菜单。

开启后，在已连接的测试群发一条**新**语音，语音中带机器人称呼和具体问题。微信生成文字后，小汐在下一次读取中按该群原有的接话规则处理。如果开启时窗口已有语音，程序把它当作历史基线。微信返回“转文字失败，请重试”时，小汐会保留等待状态；后续同条语音转写成功只触发一次。在“连接与状态”的群卡片中可看到最近一次语音是等待转写还是已经读到转写。这个状态不证明接收方手机已收到回复。

如果设置页没有这一项，或当前语音始终没有生成文字，可以对这条语音手动选择“转文字”。内置原生接收器只取得该群的可访问文字和临时消息 ID，没有能绑定原声的文件句柄。它不按时间猜录音，不读取其他聊天或微信数据库。麦克风输入转文字是微信另一项功能。

## 将自己选择的录音转成可编辑文字

打开“本地试聊”中的“本机语音转文字”，选择 PCM 16 位 WAV 和录音语言，再点“转成文字”。支持 8–48 kHz、单声道或双声道、最长 120 秒、最大 8 MiB。识别器只接收所选文件的字节，不开启麦克风。面板显示使用的引擎；可以先改错别字，再把文字插入试聊草稿。点击试聊的发送按钮才会将草稿交给配置的聊天模型。这一步不会往微信群发送消息。

**普通话**可在仓库目录使用以下命令安装轻量 Vosk 中文模型。安装器把独立 Python 环境放在 `runtime/asr/`，把模型放在 `runtime/asr_models/`；常规 npm 安装不下载这些组件。录音始终在本机识别。建议使用 Python 3.12，首次安装需要联网。

```sh
python -B scripts/install_voice_model.py
```

模型压缩包约 42 MiB，下载后校验固有 SHA-256。已下载官方模型 ZIP 时可用 `--archive "完整文件路径"`。也可以将 `XIAOXI_ASR_PYTHON`、`XIAOXI_VOSK_MODEL` 指向已有解释器和解压后的模型目录，两个值都用绝对路径。使用已有解释器须已安装 `vosk==0.3.45`。安装后的模型按次启动，空闲时不占用推理进程。[Vosk 官方模型列表](https://alphacephei.com/vosk/models)

在 Windows 上，不安装 Vosk 也可选择系统已安装的中文或英语识别器。它的识别效果依赖语言组件与录音，特别留意近音人名、时间和数字。Win32 接口、ASR 与聊天模型分别配置。[Microsoft System.Speech 文档](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine?view=netframework-4.8.1)

## 传输插件提供了真正绑定的录音

已能取得原声的受信任传输插件，可在**授权群的新语音行**提供形如 `attachments: [{kind:"audio",available:true,resourceId:"opaque_123"}]` 的句柄，示例语音行的 `klass` 为 `mmui::ChatVoiceItemView`、`text` 为 `语音3"秒未播放`、`id` 为该条消息 ID。配套的 `media` 插件必须为同一个本机会话 ID、消息 ID 和句柄返回 `source:"wechat_attachment"`、实际音频字节及 MIME。不可把聊天里出现的路径或存储时间当作绑定证据。

再将以下条目加入部署者自己的 `extensions` 并重启。自带的 ASR 插件处理 PCM WAV。其他容器格式须由传输或媒体插件核验归属后转换。本机文件面板无需任何传输插件。

```json
{"module":"./plugins/local_speech.mjs","options":{"language":"zh-CN"}}
```

新语音从群接收入口自动识别并进入原有回复规则；模型能区分平台转写与本机 ASR。暂停、断开或同一条语音已有微信转写时会取消过时的识别；重复回调不会发出第二条回复。本机文件选择的音频没有群身份，只能进入面板草稿。[插件实现契约](EXTENDING.md)
